# Requirements Document

## Introduction

The ScanCard Android application currently has only 1% optimization as reported by Google Play Console. The application requires R8 obfuscation to be enabled to meet the Google Play optimization target of 25% or higher. This document defines the requirements for configuring R8 obfuscation, code shrinking, and optimization for the ScanCard application.

## Glossary

- **R8**: Google's code shrinker and obfuscator, the successor to ProGuard.
- **Shrinking**: The process of removing unused code from the application.
- **Obfuscation**: The process of renaming classes, methods, and fields to make reverse engineering difficult.
- **Optimization**: The process of optimizing code through inlining, dead code elimination, and other transformations.
- **ProGuard Rules**: Configuration rules in proguard-rules.pro that control R8 behavior.
- **consumer-rules**: R8 rules provided by library authors, bundled in AAR files.
- **keep rules**: Rules that protect specific classes from being obfuscated or removed.
- **mapping.txt**: File generated by R8 that maps obfuscated names to original names for deobfuscation.
- **minSdk**: Minimum Android API level the app supports.
- **targetSdk**: Target Android API level for the app.

## Requirements

### Requirement 1: R8 Obfuscation Enablement

**User Story:** As a developer, I want to enable R8 obfuscation so that the app meets Google Play optimization requirements.

#### Acceptance Criteria

1. THE Release_Build SHALL set `isMinifyEnabled = true` to enable R8 code shrinking and obfuscation.
2. THE Release_Build SHALL set `isShrinkResources = true` to enable resource shrinking.
3. THE Release_Build SHALL set `isDebuggable = false` to ensure obfuscation is applied.
4. THE Release_Build SHALL generate a mapping.txt file in the outputs directory for deobfuscation of crash logs.
5. THE Release_Build SHALL include the ProGuard rules file in the release build configuration.

### Requirement 2: Application Class Preservation

**User Story:** As a developer, I want to preserve the Application class from obfuscation so that the app starts correctly.

#### Acceptance Criteria

1. THE ProGuard_Configuration SHALL include `-keep public class com.plath.scancard.ScanCardApplication { *; }` to preserve the Application class referenced in AndroidManifest.xml.
2. THE ProGuard_Configuration SHALL include `-keep public class com.plath.scancard.MainActivity { *; }` to preserve the main Activity referenced in AndroidManifest.xml.
3. THE ProGuard_Configuration SHALL NOT include broad `* extends android.app.Service` or `* extends android.app.Activity` wildcards; manifest-referenced components are kept explicitly and all others are delegated to AAPT2 auto-keep.

### Requirement 3: Domain Model Preservation

**User Story:** As a developer, I want to preserve domain model classes from obfuscation so that JSON serialization and database operations work correctly.

#### Acceptance Criteria

1. THE ProGuard_Configuration SHALL include `-keep class com.plath.scancard.domain.model.** { <fields>; }` to preserve domain model field names while allowing method shrinking and obfuscation.
2. THE ProGuard_Configuration SHALL include `-keepclassmembers enum com.plath.scancard.domain.model.**` with `values()` and `valueOf(String)` to preserve Room TypeConverter enum deserialization.
3. THE ProGuard_Configuration SHALL NOT include broad `-keep class com.plath.scancard.data.** { *; }` rules; repository, worker, and ML manager classes are delegated to R8 reachability analysis. Only `-keep class com.plath.scancard.data.ml.ExtractedCard { <fields>; }` and `-keep class com.plath.scancard.data.local.Converters { *; }` are kept.

### Requirement 4: Hilt Dependency Injection Preservation

**User Story:** As a developer, I want to preserve Hilt-generated classes from obfuscation so that dependency injection works correctly.

#### Acceptance Criteria

1. THE ProGuard_Configuration SHALL delegate Hilt keep rules to the consumer-rules provided by the hilt-android library.
2. THE ProGuard_Configuration SHALL include `-keepattributes *Annotation*` to preserve annotation metadata required by Hilt.
3. THE ProGuard_Configuration SHALL NOT include broad `-keep class dagger.hilt.** { *; }`, `-keep class javax.inject.** { *; }`, or `-dontwarn` rules; Hilt internals are delegated to consumer-rules and verified by Appium E2E (launch, database, worker flows).

### Requirement 5: Room Database Preservation

**User Story:** As a developer, I want to preserve Room database classes from obfuscation so that database operations work correctly after obfuscation.

#### Acceptance Criteria

1. THE ProGuard_Configuration SHALL delegate Room keep rules to the consumer-rules provided by the room library.
2. THE ProGuard_Configuration SHALL include `-keep @androidx.room.Entity class * { <fields>; }` to preserve Room entity field names referenced by manual Migration SQL.
3. THE ProGuard_Configuration SHALL include `-keep class * extends androidx.room.RoomDatabase` to preserve Room database subclasses.
4. THE ProGuard_Configuration SHALL include `-keep @androidx.room.Dao interface *` to preserve Room DAO interfaces.
5. THE ProGuard_Configuration SHALL include `-keep class com.plath.scancard.data.local.Converters { *; }` to preserve Room TypeConverters.

### Requirement 6: ML Kit Preservation

**User Story:** As a developer, I want to preserve ML Kit classes from obfuscation so that document scanning and text recognition work correctly.

#### Acceptance Criteria

1. THE ProGuard_Configuration SHALL delegate ML Kit keep rules to the consumer-rules provided by the mlkit-document-scanner and mlkit-text-recognition libraries.
2. THE ProGuard_Configuration SHALL NOT include broad `-keep class com.google.mlkit.** { *; }` rules that would inhibit shrinking.
3. THE ProGuard_Configuration SHALL include `-keep class com.google.mlkit.vision.documentscanner.GmsDocumentScannerOptions { *; }` if consumer-rules are insufficient.
4. THE ProGuard_Configuration SHALL include `-keep class com.google.mlkit.vision.documentscanner.GmsDocumentScanningResult { *; }` if consumer-rules are insufficient.

### Requirement 7: LiteRT LM (Gemma) Preservation

**User Story:** As a developer, I want to preserve LiteRT LM classes from obfuscation so that on-device AI inference works correctly.

#### Acceptance Criteria

1. THE ProGuard_Configuration SHALL delegate LiteRT LM keep rules to the consumer-rules provided by the litertlm-android library.
2. THE ProGuard_Configuration SHALL include `-keep class com.google.ai.edge.litertlm.Engine { *; }` to preserve the LiteRT engine class.
3. THE ProGuard_Configuration SHALL include `-keep class com.google.ai.edge.litertlm.EngineConfig { *; }` to preserve the engine configuration class.
4. THE ProGuard_Configuration SHALL include `-keep class com.google.ai.edge.litertlm.Conversation { *; }` to preserve the conversation class.
5. THE ProGuard_Configuration SHALL include `-keep class com.google.ai.edge.litertlm.ConversationConfig { *; }` to preserve the conversation configuration class.
6. THE ProGuard_Configuration SHALL include `-keep class com.google.ai.edge.litertlm.Contents { *; }` to preserve the contents class.
7. THE ProGuard_Configuration SHALL include `-keep class com.google.ai.edge.litertlm.Content { *; }` to preserve the content class.
8. THE ProGuard_Configuration SHALL include `-keep class com.google.ai.edge.litertlm.Message { *; }` to preserve the message class.
9. THE ProGuard_Configuration SHALL include `-keep class com.google.android.play.core.aipacks.AiPackManager { *; }` to preserve AI Pack manager.

### Requirement 8: WorkManager Preservation

**User Story:** As a developer, I want to preserve WorkManager classes from obfuscation so that background tasks work correctly.

#### Acceptance Criteria

1. THE ProGuard_Configuration SHALL delegate WorkManager keep rules to the consumer-rules provided by the work-runtime-ktx library.
2. THE ProGuard_Configuration SHALL include `-keep class * extends androidx.work.Worker` to preserve custom Worker classes.
3. THE ProGuard_Configuration SHALL include `-keep class * extends androidx.work.ListenableWorker` to preserve custom ListenableWorker classes.

### Requirement 9: Build Verification

**User Story:** As a developer, I want to verify that the R8 configuration is correct and the build succeeds.

#### Acceptance Criteria

1. THE Build_Verification SHALL run `./gradlew :app:assembleRelease` successfully without errors.
2. THE Build_Verification SHALL verify that the generated APK or AAB file is created in the outputs directory.
3. THE Build_Verification SHALL verify that the mapping.txt file is generated for deobfuscation.
4. THE Build_Verification SHALL verify that obfuscated class names appear in the generated APK or AAB.
5. THE Build_Verification SHALL run `./gradlew :app:analyzeReleaseR8Config` to verify keep rules are correctly applied.

### Requirement 10: Google Play Optimization Target

**User Story:** As a developer, I want to achieve at least 25% optimization as reported by Google Play Console.

#### Acceptance Criteria

1. THE Optimization_Metric SHALL achieve at least 25% optimization ratio as reported by Google Play Console after uploading the release build.
2. THE Optimization_Metric SHALL verify that unused resources are removed through resource shrinking.
3. THE Optimization_Metric SHALL verify that unused classes are removed through code shrinking.
4. THE Optimization_Metric SHALL verify that the app launches and functions correctly after obfuscation.

### Requirement 11: Runtime Verification

**User Story:** As a developer, I want to verify that the app functions correctly after R8 obfuscation.

#### Acceptance Criteria

1. THE Runtime_Verification SHALL verify that database operations work correctly after obfuscation.
2. THE Runtime_Verification SHALL verify that network requests and responses are handled correctly.
3. THE Runtime_Verification SHALL verify that Hilt dependency injection works correctly at runtime.
4. THE Runtime_Verification SHALL verify that WorkManager background tasks execute correctly.
5. THE Runtime_Verification SHALL verify that ML Kit document scanning and text recognition work correctly.
6. THE Runtime_Verification SHALL verify that LiteRT LM AI inference works correctly.
7. THE Runtime_Verification SHALL compare release behavior against the debug baseline via Appium E2E; identical behavior on both builds proves no R8 regression.

### Requirement 12: Error Handling and Debugging

**User Story:** As a developer, I want to be able to debug issues that occur after obfuscation.

#### Acceptance Criteria

1. IF R8 build fails due to missing keep rules, THEN THE Build_System SHALL output a clear error message indicating which class is affected.
2. IF runtime errors occur after obfuscation, THEN THE Developer SHALL use mapping.txt to deobfuscate stack traces.
3. IF a library requires additional keep rules, THEN THE Developer SHALL add them to proguard-rules.pro following consumer-rules patterns.
4. IF obfuscation causes runtime issues, THEN THE Developer SHALL use `-dontobfuscate` for affected classes as a temporary workaround.
